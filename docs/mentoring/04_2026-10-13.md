## 3. 기능별 삽 결과

모두 로컬에서 돌렸습니다. 숫자는 이 시험 조건에서 나온 값입니다. 오류를 섞은 시험의 오류는 우리가 만든 것이라 실제 사진의 오류와 분포가 다를 수 있습니다.

### 3.1 OCR (채연)

| 항목 | 요약 |
|---|---|
| 넣은 것 | CLOVA OCR로 가짜 처방전을 읽고, 약 이름을 급여목록(22,045개)에서 찾고, 안전성 점검 7개 항목을 돌리는 흐름 |
| 나온 것 | 처방전 1장이 1.46초에 읽힘. 사진 17장 중 16장에서 약 이름이 모두 맞는 약으로 이어짐. 안전성 점검 7개 항목이 모두 경고를 냈고 기대하지 않은 경고는 0건 |
| 잘 된 것 | 오류를 섞어 시험해 조용히 틀리는 경우를 찾아 고친 개선안이 숫자 오독으로 줄 수가 틀린 132번 중 132번을 0으로 줄임 |
| 막힌 것 | 질병분류기호 I10을 한 번도 맞게 읽지 못함. 많이 흐린 사진은 읽지 못함. 개선안은 원본 코드에 아직 안 넣음 |
| 확인하지 못한 것 | 실제 처방전과 폰 사진, 실제 병원 양식 |

#### 한 일

- 사진 23장으로 CLOVA를 23번 호출했습니다(경고가 걸리는 조합 4장, 그 사진을 망가뜨린 10장, 약 이름이 두 줄로 나뉜 3장, 표 모양이 다른 6장).
- 그다음 CLOVA와 AI를 다시 부르지 않고 저장된 결과, 약제급여목록, 상병마스터(21,299개)에 오류를 섞어 약 이름 매칭, 질병분류기호 보정, 표 읽기를 시험했습니다(비용 없음). 원본 코드는 고치지 않고 개선안을 새 파일로 만들어 같은 시험을 다시 돌렸습니다.

#### 실제 CLOVA 호출 결과

- 처방전 1장이 1.46초에 읽혔습니다(글자 묶음 84개, 평균 확실도 0.938).
- 사진 17장 중 16장에서 약 이름이 모두 맞는 약으로 이어졌습니다. 글자가 깨진 이름("밀ㄹ그램")도 점수 0.74 이상으로 맞았고, 흐림 2단계, 기울임 5도와 12도, 해상도 3분의 1, JPEG 15, 어두움, 노이즈, 그림자, 폰 느낌, 표 모양이 다른 6장도 모두 맞았습니다.
- 안전성 점검 7개 항목이 모두 경고를 냈고 기대하지 않은 경고는 0건이었습니다. 경고 5종은 심평원 DUR 원본의 같은 행과 일치했습니다.

#### 오류를 섞어 시험한 결과 (원본과 개선안 비교)

| 항목 | 원본 | 개선안 |
|---|---|---|
| 숫자 2개를 글자로 오독했을 때 약 줄 수가 틀린 경우 | 132번 중 132번 | 0 |
| 15도 기울임에서 틀린 숫자가 조용히 확정된 줄 | 86건 | 0건 (6장은 다시 찍기 안내) |
| 교부일 오독으로 프로그램이 멈춤 | 132번 중 88번 | 0 (교부일 확인 표시로 넘김) |
| 질병분류기호 첫 글자가 닮은 숫자로 읽힌 경우 엉뚱한 코드로 자동 보정 | 8% | 0% |
| 4글자 코드 첫 글자가 빠진 경우 엉뚱한 코드로 자동 보정 | 60% | 0% |

개선안(새 파일, 시험 15개 통과)은 사진 기울기를 재서 바로잡고 한도를 넘으면 "다시 찍어 주세요"로 보냅니다. 숫자 칸의 숫자 아닌 글자는 지워 빈 칸으로 두고, 질병분류기호는 후보가 하나일 때만 자동 보정합니다. 숫자 범위 검사(1회량, 횟수, 일수)는 흔한 처방 200개를 잘못 막은 경우가 0이었고 숫자 오독 2,890가지 중 56%를 잡았습니다.

#### 약 이름 매칭

- 이름에 OCR식 오류를 넣은 질의 2,860개에서 86%는 정확한 약으로 찾았고, 11%는 사용자가 고르거나 찾지 못함으로 넘어갔습니다. 먹는 약만 보면 성분이 다른 약을 조용히 확정한 비율은 0.05%입니다.
- 점수가 낮은 줄은 "찾지 못했어요, 확인해 주세요"로 보내고 안전성 점검에서 뺍니다(점수 0.60 미만, 이름 4글자 미만, 이름 앞부분이 후보와 절반 미만으로 겹침). 많이 흐린 사진이 이 규칙으로 구분되지만(이름 점수 0.40에서 0.42, 맞게 이어진 이름은 0.74 이상) 사진 17장으로 정한 값이라 확정하기는 이릅니다.

#### 질병분류기호

- I10을 한 번도 맞게 읽지 못했습니다(사진 17개 중 "110" 13개, "10" 4개). 개선안은 "110" 13개를 모두 I10으로 돌려놓지만, 끝 숫자나 영문자가 다른 유효한 코드로 바뀐 오독(3글자 코드의 81%와 77%)은 목록 검사로 알 수 없습니다.
- 그래서 항상 사용자 확인으로 보냅니다(수인과 합의). 하나로 바로잡히면 "인식한 질병은 본태성 고혈압(I10)이에요. 맞나요?", 후보가 여러 개면 고르기, 목록에 없으면 직접 입력이나 건너뛰기입니다.
- 안전성 점검은 질병분류기호를 쓰지 않아 [분석 시작]은 막지 않고, 확인 전에는 생활습관 안내만 잠급니다. 약 이름을 읽지 못한 줄은 맞는 약 고르기나 "이 약은 빼고 진행", 처방전 전체를 못 읽으면 다시 찍기나 직접 입력으로 보냅니다.

#### 표 읽기와 사진 기울기

- 숫자를 읽은 순서로 나누면 칸이 밀리고 이름이 두 줄 이상이면 둘째 줄이 다른 약으로 읽혔습니다(폰 사진에서 약이 5개로 세어져 "다제약물" 경고가 거짓으로 나옴). 칸 위치와 줄 간격 기준으로 고쳐 모두 맞았습니다.
- 사진이 15도 기울면 원본은 38%가 조용히 틀렸고, 개선안은 20도를 넘으면 다시 찍기로 보내 조용히 틀린 숫자가 0%입니다.

#### 안전성 점검 코드 시험 (AI 호출 없음)

규칙마다 그 규칙에 걸리는 환자와 약을 만들어, 경고가 뜨는지와 걸리지 않는 환자에게는 뜨지 않는지를 봤습니다. 규칙이 많은 항목은 무작위 표본입니다(시드 고정).

| 항목 | 결과 |
|---|---|
| 병용금기 | 조건 없는 규칙 800개 중 797개 경고, 놓침 0 (3개는 예외 제품만 있어 건너뜀). 성별 "모두" 규칙 583개, 복합제 규칙 500개도 모두 잡음 |
| 연령금기 | 해당 나이 197개 모두 경고, 해당하지 않는 나이 206개 모두 경고 없음 |
| 1일 최대용량 | 기준의 1.5배 487개 모두 경고, 0.5배 487개 모두 경고 없음 |
| 노인주의, 동일성분 중복, 효능군 중복, 다제약물 | 모두 맞음 (효능군은 41개 계열 중 40개, 나머지 1개는 동일성분으로 먼저 잡힘) |

| 속도 | P50 27.8ms, P95 30.1ms, 최대 120ms (DB 점검 시간만) |

- 복합제 틈: 복합제 성분코드 670개 중 100개(15%, 제품 약 478개)는 자기 코드로는 병용금기가 없는데 들어 있는 성분은 단독으로 병용금기가 있습니다(아세트아미노펜과 트라마돌, 아스피린과 클로피도그렐 등). 구성 성분까지 보는 확장판(새 파일)은 틈이 있는 96건 중 92건에서 경고를 냈고, 나머지 4건은 심평원 예외 규정이 맞게 적용된 경우였습니다. 단일 성분 처방 250건은 원본과 결과가 같았습니다. 약사 검토 후에 켜는 것을 권합니다.
- 출생연도를 못 읽었거나 미래 연도면 원본은 노인주의와 연령금기 점검에서 멈추거나 엉뚱한 경고를 띄웠습니다. 보강판은 나이가 들어가는 점검만 건너뛰고 건너뛴 항목을 돌려줍니다(새 파일, 시험 4개 통과).

#### 막힌 것

#### 확인하지 못한 것

- 실제 처방전과 폰 사진: 시험 사진은 가짜 양식에 글자를 다시 쓴 합성 사진이라 실제 병원 양식(칸 선이 다른 것, 머리글이 두 줄인 것)과 이름이 네 줄 이상인 경우는 모릅니다.

- 경고 문구와 등급이 의학적으로 맞는지, 숫자 범위 기준이 적절한지는 판단하지 않았습니다(약사 검토 필요).

### 3.2 RAG: 허가정보 확인과 안내문 (채연)

| 항목 | 요약 |

#### 허가정보 확인

- 식약처 허가정보 21,924건의 용법용량과 주의사항을 읽는 규칙을 만들어, 챗봇이 "약을 깜빡했어요"에 답할 근거가 있는지 확인했습니다. 빠뜨렸을 때 안내가 있는 약은 내복약 17,381개 중 1,330개(7.7%)입니다. 당뇨약(A10) 24%, 항응고제(B01) 24%, 항경련제(N03) 30%는 있고 혈압약(C09, C10)과 스타틴은 거의 0입니다.
- 내복 무작위 40개를 읽어 보니 모두 진짜 복용 누락 안내였습니다. 규칙이 놓친 약이 있는지는 확인하지 못했습니다. 외용약 1,636개는 전부 용법용량 글이 있습니다(안약 810개, 패치 104개 포함).

#### 안내문 AI 시험 (gpt-4o-mini, 약 6개를 방법마다 1번씩)

- 방법: A 1차 안내문, B A를 휴머나이저 규칙으로 다듬은 것, C v6 프롬프트만 쓴 방식, D v6 프롬프트에 도구(근거 읽기, 검사, 제출)를 더한 방식, E B를 사람이 근거 원문과 보고 고친 것.
- AI 호출 12번(약 75초) 뒤, AI 없이 저장된 결과를 9가지로 넓힌 검사로 다시 보고 규칙으로 자동 고치는 후처리(auto_fix.py)를 만들었습니다.

| 방법 | 처음 돌린 결과 | 넓힌 검사로 다시 본 것 | 자동 고침 뒤 |
|---|---|---|---|
| A 1차 안내문 | 3개 약, 5건 | 3개 약, 5건 | 5건 |
| B 스킬 다듬기 | 3개 약, 3건 | 3개 약, 3건 | 3건 |
| C 프롬프트만 | 3개 약, 3건 | 4개 약, 6건 | 2건 |
| D 프롬프트와 도구 | 2개 약, 4건 (2개는 결과를 못 냄) | 5개 약, 9건 | 3건 |
| E 사람이 근거를 고친 안 | 0건 | 0건 | 0건 |

- 정정: 전에 "D는 자동 검사 문제 0건"이라고 한 것은 검사가 약했기 때문이고, 넓힌 검사에서는 D도 9건이 나왔습니다.
- 자동 고침은 급한 말 낮추기, 어려운 말 풀기, 용량 문장 정리 등을 하고, 고친 뒤 문제가 줄지 않으면 고침을 버립니다. 일부러 만든 나쁜 문장(유형마다 200개)은 모든 유형을 잡았고, 멀쩡한 문장 300개 중 잘못 잡은 것은 1개였습니다.

#### 생활습관 안내와 어려운 병 이름 (AI 호출 없음)

- 먹는 약 17,450개 전체에 약 연결 규칙을 돌려 보니 놓친 약은 없었고, 허가정보의 ATC가 틀린 16개 제품이 엉뚱한 계열로 걸려 보강판(새 파일)이 이 16개만 뺍니다. 폐동맥고혈압 약을 빼는 것은 의료 검수가 필요합니다.
- 허가정보 주의사항의 5글자 이상 병 이름 898종 중 262종(나온 횟수 기준 87.7%, 전에는 1.5%)을 쉬운 말로 바꾸게 했고, 병 이름이 없는 문장 5,000개는 바뀌지 않았습니다. 풀이 말은 의료진 검수 전 초안입니다.

#### 막힌 것

- 자동 고침으로 못 고치는 것은 사람이 읽어야 합니다. 쉬운 말로 바꿀 말이 없는 것("교감신경 약과 함께"), 근거에 없는 증상("가벼운 두통"), 병 이름을 3개 나열한 쓰임 문장, 문장 뜻이 근거와 맞지 않는 것(A, B)입니다.
- 용량 문장을 "처방받은 대로 드세요"로 바꾸면 "저용량에서 시작"이라는 정보가 사라지고, 알릴 내용을 더하면 "몸에 이상이 있으면"이라는 조건이 새로 붙습니다. 환자용으로 맞는지 사람이 봐야 합니다.
- 토큰은 D가 C의 약 5.5배입니다(입력 약 17만 대 3만, 시간 63초 대 15초). D는 약 하나에 도구를 10에서 17번 부릅니다. 지금까지 서비스에 넣을 후보는 사람이 확인한 E뿐입니다.

#### 확인하지 못한 것

- 방법마다 한 번씩만 돌려서 C와 D의 차이가 우연일 수 있습니다. 3번씩 돌려 확인하려면 AI 호출 비용이 듭니다.
- 자동 고침 규칙은 6개 약의 문장 10개를 보고 만들었습니다. 새 약에서도 같은 효과가 날지는 AI로 다시 돌려 봐야 합니다. 나쁜 문장 시험도 검사 규칙의 표현을 본떠 만들어서 100%는 낙관적인 값입니다.
- 외용약 안내문은 AI로 만들어 보지 않았습니다. AI 없이 확인한 것은 근거 문장이 만들어지는지로, 먹는 약과 외용약을 400개씩 뽑으니 둘 다 98에서 99%였습니다. 근거 원문에 "유산산증", "점액부종" 같은 어려운 말이 든 약은 먹는 약 14%, 외용약 5%라 AI가 쉬운 말로 풀어 써야 합니다.

  - Jev는 무료 경로가 없고 국내 카드 결제가 되지 않아 재지 못했습니다(결제가 해결되면 같은 27문장으로 잴 스크립트는 준비함).
- 1단계는 gpt-4o-mini를 그대로 씁니다.

#### 막힌 것

- 정상 질문을 위험으로 막는 문제: 2층 단독 2개 대 10개, 1층과 합쳐 4개 대 10개입니다("죽을 먹어도", "두 번 먹었는지 헷갈려요" 등). "죽을 먹어도"는 gpt-4o-mini, Solar, Llama 70B, Nemotron이 모두 막았습니다. 과다 복용과 자해 카드에는 빠져나갈 칩이 없습니다. 문장이 27개뿐이라 늘려서 다시 봐야 합니다.
- 앞에서 말한 상황을 답에 안 씀: 계층 요약이 사실을 8개 중 8개 기억해도 처음에는 답이 쓴 것이 0개였고, 사실 칸과 질환 규칙으로 4개까지 올렸습니다. 신장은 해결됐지만 검사 일정(CT)과 음식 습관(자몽)은 일반 안내만 하고, 상관없는 질문 7곳에 "말씀하신 대로 소주를 매일 드시니"처럼 사실을 끼워 넣는 부작용이 남았습니다.
- 생활습관 문장을 약 이야기로 바꿈: "술은 중성지방을 올림"을 "리피토정은 ~"처럼 말했습니다. 같은 질문 5개를 5번씩 돌려 25번 중 1번으로 드뭅니다. 문장마다 맞는 근거인지 확인하는 단계를 만들었지만 입력 토큰이 약 70% 늘어 기본은 꺼 두었습니다.
- "꼭 들어갈 것" 점수는 26문항 33 대 52입니다. 골든셋 기준 글에 화면 동작(출처 표시 등)이 섞여 있어 기준 글을 나눠야 합니다.
- 한국어 모델: Kanana는 서버(2GB)에서 직접 못 돌리고 API는 유료입니다. 서버에서 API로 쓸 수 있는 한국어 모델로 업스테이지 Solar Pro 2를 찾았지만 캠프 키 밖의 외부 API입니다.
- 근거 검색과 약 이름 검색(#51)이 임시값이라 붙어야 진짜 결과가 나옵니다.
- 자동 채점관(gpt-4o-mini)이 위험한 답을 통과시킨 적이 있어서 "들어가면 안 될 것"은 사람이 다시 봅니다.

## 5. 여쭤볼 것

각각 "여기까지 시도했고 여기서 막혔다"를 함께 적었습니다.

### 1. (채연) 안내문은 사람이 확인할까요, AI로 한 번 더 확인할까요

- 지금까지: 서비스에 넣을 안내문은 사람이 확인한 것만 쓰려고 합니다. 자동 검사와 자동 고침으로도 용량 문장과 어려운 말이 남아 사람이 읽어야 합니다.
- 여쭙고 싶은 것
  - 시연에 쓸 자주 먹는 약 몇 개만 사람이 확인해서 저장해 두는 방식으로 충분할까요, 아니면 AI로 한 번 더 확인하는 단계를 넣는 쪽이 나을까요?
  - 도구 방식(D)은 토큰이 5.5배 들어서 어디까지 쓸지 여쭙고 싶습니다.
  - 문제가 9건에서 3건으로 줄어드는 자동 고침 후처리를 써도 되는지(문장 뜻을 바꿀 수 있음) 여쭙고 싶습니다.

### 2. (채연) 복용 누락 근거가 없는 약은 어떻게 답할까요

- 지금까지: 챗봇이 "약을 깜빡했어요"에 답할 근거가 허가정보에 있는 약은 7.7%뿐입니다.
- 여쭙고 싶은 것: 근거가 없을 때 "약사에게 확인해 주세요"라는 고정 문구(no_evidence)로 답하는 것이 맞을까요, 아니면 일반 원칙("두 배로 먹지 마세요")을 보여 줘도 될까요?

### 3. (채연) 약사 등 전문가 검토를 받지 못했을 때

- 지금까지: 약 연결 성분 코드와 생활습관 팩트표는 약사나 의료 전문가 검토를 받지 못했습니다.
- 여쭙고 싶은 것
  - 팀이 1차로 확인한 기준으로 쓰고 한계를 문서에 적는 정도가 괜찮을까요?
  - 검토를 받을 현실적인 방법(학교, 캠프, 참여기업 등)이 있을까요?

### 4. (채연) 외용약 안내 범위

- 지금까지: 안내문은 먹는 약만 만들고 있습니다. 안약과 패치 같은 외용약은 허가정보에 사용법 글이 전부 있어서, 사용법만 허가정보 문장 그대로 보여 주려고 합니다.
- 여쭙고 싶은 것: MVP 범위로 적절할까요? (수인도 동의했고, 챗봇도 외용약 사용법은 그 약의 용법용량과 적용상의 주의 원문으로 답하게 합니다.)

### 5. (채연, 수인) 평가 기준 P95 3초

- 지금까지: 평가 기준에 전체 API P95 지연 3초 이내가 있습니다. 안내문은 15초에서 63초가 걸려서 비동기 방식으로 분리하려고 합니다.
- 여쭙고 싶은 것
  - 이렇게 하면 기준을 만족하는 것으로 보는지
  - 측정은 개별 API 응답 기준인지, 최종 결과가 나올 때까지인지
  - 측정값은 어떤 방식으로 제출하는지

### 6. (수인) 2층 가드레일 과차단을 줄이는 순서

- 지금까지: 2층 가드레일이 정상 질문 10개 중 4개를 막습니다(1층과 합친 값). 모델 12개를 비교해 보니 서버에서 쓸 수 있는 모델 중에는 업스테이지 Solar Pro 2(외부 API)가 1개로 가장 적게 막았지만(위험 놓침 0, 0.42초), 문장이 27개뿐이라 1개와 2개 차이는 크지 않습니다.
- 여쭙고 싶은 것: 위험을 놓치지 않는 쪽을 풀지 않으면서 과차단을 줄이려면, 모델을 바꾸는 것(Solar Pro 2, 외부 API)과 시험 문장을 늘리는 것 중 무엇이 먼저일까요?

### 7. (수인) 사용자가 말한 건강 정보의 저장과 동의

- 여쭙고 싶은 것: 사용자가 말한 건강 정보(신장, 검사 일정, 음주)를 기억해서 답에 쓰려면 저장해야 합니다. 보관 방식과 사용자 동의는 어떻게 하는 게 좋을까요?

### 8. (수인) 자동 채점을 어디까지 믿을지

- 지금까지: 챗봇 골든셋 점수를 자동 채점관(gpt-4o-mini)이 매기는데 위험한 답을 통과시킨 적이 있어서 "들어가면 안 될 것"은 사람이 다시 봅니다.
- 여쭙고 싶은 것: 자동 채점은 어디까지 믿고, 사람이 보는 비율은 어느 정도가 현실적일까요?

## 6. 조언받고 싶은 것

### 1. 실제 처방전 없이 OCR의 믿을 만한 정도 보여 드리기

- 지금까지: 가짜 처방전을 변형한 합성 사진 위주로 시험했고 실제 병원 양식을 구하기 어렵습니다.
- 여쭙고 싶은 것
  - 비식별로 구하는 방법이나 대신 쓸 만한 시험 방법이 있을까요?
  - 질병분류기호는 OCR이 틀리기 쉬워서 "맞나요?"로 확인받는 화면을 두려고 하는데 이 방향이 괜찮을까요?

### 2. 첫 배포

서버에는 Postgres, Redis, 워커, FastAPI 일꾼 3개가 함께 올라갑니다. 세 가지를 여쭙고 싶습니다.

- (a) EC2 한 대에 Docker Compose로 올리는 방식이 맞는지, 2GB(t3.small)로 시작해도 되는지. DB를 서버 안 컨테이너로 둘지 RDS로 뺄지도 같이 여쭙습니다.
- (b) Expo 앱의 배포 URL을 어떻게 낼지. 웹으로 내보낸 주소를 프론트엔드 URL로 쓸 수 있을 것 같은데, 웹에서 서버를 부르려면 서버에 CORS 설정이 필요합니다(지금은 없음). HTTPS와 도메인을 첫 배포에 넣어야 하는지도 궁금합니다.
- (c) 건강 정보를 다루는 공개 저장소 프로젝트에서 배포 전에 최소한 지켜야 할 보안 기준

### 3. 남은 기간(MVP 10/20)의 우선순위

- 지금까지: 첫 배포는 10/15를 목표로 서버가 뜨고 메모리를 재는 것까지 하려고 합니다. 지금은 기능별로 따로 시험한 상태입니다.
- 여쭙고 싶은 것
  - 그 뒤에 OCR에서 안내문, 챗봇까지 한 줄로 잇는 것과 품질 다듬기 중 무엇을 먼저 할지 의견 부탁드립니다.
  - 개선안(OCR 파이프라인, 복합제 확장, 생활습관 보강)을 원본 코드에 넣는 순서도 함께 정하려고 합니다.

### 4. 챗봇 1단계 응답 방식

- 지금까지: 서버가 답을 다 만들고 검사한 뒤 한 번에 보내고, 화면이 글자를 차례로 보여 주는 방식으로 정했습니다.
- 여쭙고 싶은 것: 대기 시간은 그대로이고 읽는 방식만 바뀌는 것인데, 고령 사용자에게 괜찮을지 의견 부탁드립니다.

### 결정된 사항

- OCR 후보정은 규칙, 비슷한 이름 추천, LLM 순서. LLM은 기본 꺼 두고 어떤 후보든 사용자가 고름
- 비처방전 사진은 호출 전에 거르지 않고, 하루 업로드는 사용자당 30장
- 약 이름은 글자 조각으로 찾고 임베딩은 챗봇 근거 검색에만 씀. 근거 충분성 판정은 검색 함수가 하고, 결과의 완전, 부분, 없음(coverage)으로 챗봇이 답을 고름
- 안내문은 미리 만들어 저장하고 승인된 것만 보여 줌
- 건강 정보는 가입과 내 정보로 나누어 받음. 별명은 뺌
- 가드레일은 regex, 문맥 파악, LLM 순서. 2층이 응답하지 않으면 1층만으로 답하지 않고 답변 오류(E6)로 보냄
- 배포는 다음 멘토링까지 하지 않음. 성능은 완성 뒤 Locust로 측정
