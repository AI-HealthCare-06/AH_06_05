## 3. 현재 막힌 문제 / 검증이 필요한 사항

1. **[인프라]** 2GB 서버 1대에 전부 올리기 — 성규
   - 판단 근거: 조교님 안내로 서버는 팀이 직접 만들고 사양도 팀이 정함 → t3.small(2GB) 1대에 nginx · FastAPI · PostgreSQL · Redis · ai-worker를 올리기로 함. 워커는 가벼운 arq(약 31MB), ai-worker는 768M로 제한, torch 제거
   - 확인하고 싶은 점: 이 구성이 현실적으로 괜찮은지, 줄인다면 어떤 서비스부터인지
2. **[RAG]** AI가 쓴 안내문 검증 — 채연
   - 판단 근거: 안전성 점검(병용금기 · 연령금기 등)은 DB 조회로만 하고(시험 39개 통과), AI는 허가정보를 쉬운 말로 바꾸는 데만 씀. 10/2에 gpt-4o-mini로 약 6개 × 3번 시험하며 프롬프트를 5번 고침
     - v1: 숫자만 검사 → 허가정보에 없는 증상(어지러움 · 술)과 "복용을 중단하세요"가 그대로 나옴
     - 지금(v5): 허가정보 문장마다 번호를 붙이고 AI가 근거 번호를 같이 내게 함 → 증상이 근거에 있는지 · 약을 끊게 하는 말 · 의사용 말을 규칙으로 거름 → 화면에 지어낸 내용 0건, 전부 통과 13~16/18
     - 같은 약은 한 번 만든 문장을 저장해 다시 씀 (돌릴 때마다 글자가 달라서)
   - 확인하고 싶은 점: 규칙으로 막기 어려운 어색한 문장이 남는데, 시연할 자주 먹는 약은 사람이 한 번 확인해서 저장해 두는 방식이면 괜찮을지, 아니면 AI로 한 번 더 확인하는 게 나을지
3. **[챗봇]** 답변을 글자 단위로 바로 보여 줄지 — 수인
   - 판단 근거: 글자 단위로 바로 보여 주면 근거 검증에 걸려도 사용자가 이미 읽은 뒤라서, 업계 권고(AWS · OpenAI 모두 민감한 서비스는 검사 후 표시)에 따라 1단계는 "다 만든 뒤 한 번에 표시"로 가려 함
   - 확인하고 싶은 점: 고령 사용자에게 기다리는 시간이 문제가 될 것 같은데, 어떻게 풀면 좋을지
