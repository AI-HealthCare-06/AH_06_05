### 문의 1. 타겟 사용자 정의 및 플랫폼 선택

**배경**

필수 구현 요구사항에 "진료 기록, 처방전, 약봉투 등을 이미지·PDF로 업로드"가 포함되어 있습니다. 저희는 이를 의료인이나 약사가 아닌 **일반 환자·보호자의 행동**으로 해석했습니다. 의료인·약사는 EMR 및 조제 시스템에서 원본 데이터를 직접 확인하므로 촬영·업로드 과정이 불필요하기 때문입니다.

**팀 검토안**

- 타겟 사용자: **일반 환자 및 보호자** (다약제를 복용하는 고령 만성질환자와 이를 돕는 가족)
- 플랫폼: **모바일 퍼스트 반응형 웹 + PWA**
  - 실제 사용 맥락(병원·약국에서의 즉시 촬영, 복약 알림)이 모바일 환경이라고 판단
  - 네이티브 앱은 캠프 배포 환경(FastAPI/Docker/EC2) 및 기간상 어려워 확장 계획으로 문서화 예정

**문의드릴 점**

1. 타겟 사용자를 "일반 환자 및 보호자"로 확정해도 되는지, 의료인·약사 대상이 아닌 것이 맞는지
2. 참여기업이 특정 타겟을 염두에 두고 주제를 제시하였는지
3. 모바일 퍼스트 반응형 웹 + PWA 방향이 적절한지
4. 고령층을 주 타겟으로 할 경우 요구되는 접근성 수준 (큰 글씨, 음성 안내 등)

---

### 문의 2. 역할 분담 구조

**배경**

본 주제는 자체 모델 학습 없이 외부 API 연동(OCR · LLM · RAG) 중심으로 구성되어, AI 구현 작업이 사실상 백엔드 영역에 포함된다고 판단했습니다.

**팀 검토안**

AI 전담자를 별도로 두지 않고 다음과 같이 분담합니다.

- 백엔드 2인: AI 파이프라인 구현 (OCR 연동, RAG 검색, LLM 체인, 비동기 처리)
- PM: AI 품질 관리 (프롬프트 설계, 실험 기록, 결과 편차 검증)

**문의드릴 점**

1. AI 전담자가 없는 구조가 평가상 불리하지 않은지
2. 프론트엔드 1인 체제가 현실적인지 (화면 6~8개 예상)
3. 인프라·배포(Docker/EC2)가 백엔드 1인에게 집중되어 있는데 분산이 필요한지
4. PM이 기획과 AI 품질 검증을 병행하는 것이 무리는 아닌지

---

### 문의 3. 진료기록(민감정보) 처리 방침

**배경**

진료 기록은 민감정보에 해당하여 저장 범위를 최소화하고자 합니다. 다만 필수 요구사항 중 챗봇의 "이전 대화 맥락 반영" 조건이 있어 완전 미저장은 불가능하다고 판단했습니다.

**팀 검토안**

- 업로드된 **원본 이미지는 저장하지 않고** OCR 처리 후 즉시 폐기
- **추출된 텍스트(약품명·용량·복용법)만 암호화 저장**
- 성명·주민등록번호 등 식별정보는 저장 전 마스킹

**문의드릴 점**

이 수준의 개인정보 처리 방침이 적절한지, 참여기업이 기대하는 수준과 부합하는지

---

### 문의 4. RAG 지식베이스 데이터 출처 및 API 사용 가능 여부

**배경**

LLM이 약품 정보를 임의로 생성하는 문제를 방지하기 위해, 공신력 있는 외부 데이터를 검색해 근거로 삼는 RAG 구조를 적용하려 합니다.

**팀 검토안**

식약처 공공데이터 API를 지식베이스로 활용
- 의약품개요정보 (e약은요) — 약효·용법·주의사항
- DUR 품목정보 — 병용금기·연령금기

정부 기관 출처로 근거 신뢰성을 확보할 수 있고, DUR 정보까지 반영하면 안전성 측면의 차별점이 될 것으로 판단했습니다.

**문의드릴 점**

1. 해당 공공 API를 프로젝트에 사용해도 되는지
2. **팀원(PM)이 이전에 개인 명의로 발급받아 둔 무료 공공데이터 API 키를 본 프로젝트에 사용해도 무방한지** (필요 시 팀 공용으로 재발급 예정)
3. 그 외 권장하시는 데이터 출처가 있는지

---

### 문의 5. API 응답 성능 기준(P95 Latency 3초) 대응 방안

**배경**

평가 기준에 "전체 API의 P95 Latency 3초 이내"가 명시되어 있으나, OCR → RAG 검색 → LLM 생성으로 이어지는 파이프라인은 수십 초가 소요될 것으로 예상됩니다.

**팀 검토안**

안내문 생성을 **비동기 작업으로 분리**
- 요청 시 즉시 `job_id` 반환 → API 응답 자체는 3초 이내 충족
- 클라이언트가 폴링하여 완료 시 결과 표시
- 대기 중 진행 단계를 UI로 안내

**문의드릴 점**

이 해석이 맞는지, 평가 시 Latency 측정 대상이 어디까지인지 (개별 API 응답 기준인지, 최종 결과 도출까지인지)

---

### 문의 6. 선택 구현 범위

**배경**

실제 기능 개발 기간이 4주(09/30 ~ 10/27)로, 필수 구현 3개(OCR 인식 · LLM 가이드 생성 · 실시간 챗봇)만으로도 일정이 빠듯하다고 판단했습니다.

**팀 검토안**

- 선택 구현은 **"시각/음성 콘텐츠 변환(TTS)" 1개**만 진행
  - 타겟이 고령층 및 보호자인 만큼 음성 안내가 서비스 방향과 부합
- 나머지(이미지 분류 기반 복약 분석, 알림 기능)는 **확장 계획으로 문서화**

**문의드릴 점**

범위 축소가 과도하지 않은지, 평가상 선택 구현 개수가 중요한 요소인지
