### 현재 막힌 문제 / 검증이 필요한 사항

#### 1. [역할 분담] 아래 구조가 적절한지 봐주셨으면 합니다

**판단 근거**
주제 2는 모델 학습이 없고 외부 API 연동(OCR / LLM / RAG) 중심이라 "AI 작업 = 백엔드 코드"라고 판단했습니다. 그래서 AI 전담자를 따로 두지 않고, 백엔드 2명이 파이프라인을 구현하고 PM이 프롬프트 설계·실험 기록·결과 편차 검증을 맡는 구조로 정했습니다.

**확인하고 싶은 점**
1. AI 전담자가 없는 구조가 평가상 불리하지 않은지
2. 프론트엔드 1인 체제가 현실적인지 (화면 6~8개 예상)
3. 인프라·배포(Docker/EC2)를 백엔드 1명에게 몰았는데 부하 분산이 필요한지
4. PM이 기획과 AI 품질 검증을 겸하는 것이 무리는 아닌지

#### 2. [설계] 진료기록(민감정보) 저장 방침

**판단 근거**
"원본 이미지 미저장 + 추출 텍스트만 암호화 저장(식별정보 마스킹)" 방침을 세웠습니다. 필수 요구사항에 챗봇의 "이전 대화 맥락 반영"이 있어 완전 미저장은 불가하다고 판단했습니다.

**확인하고 싶은 점**
이 수준의 개인정보 처리 방침이 적절한지, 참여기업이 기대하는 수준과 맞는지

#### 3. [AI] RAG 지식베이스 데이터 출처

**판단 근거**
LLM 환각 대응을 위해 식약처 공공 API(의약품개요정보 "e약은요", DUR 품목정보)를 지식베이스로 사용하려 합니다. 정부 출처라 근거 신뢰성이 확보되고, DUR(병용금기·연령금기)까지 반영하면 서비스 차별점이 된다고 판단했습니다.

**확인하고 싶은 점**
- 참여기업 의도와 맞는 방향인지
- 다른 권장 데이터 출처가 있는지
- API 신청 승인에 시일이 걸릴 수 있어, 지금 신청해도 되는지

#### 4. [성능] P95 Latency 3초 기준 대응 방안

**판단 근거**
평가 기준에 "전체 API의 P95 Latency 3초 이내"가 있으나, OCR → RAG 검색 → LLM 생성 파이프라인은 수십 초가 소요됩니다. 안내문 생성을 비동기 작업(즉시 `job_id` 반환 후 폴링)으로 분리하면 API 응답 자체는 3초를 충족할 수 있다고 이해했습니다.

**확인하고 싶은 점**
이 해석이 맞는지, 평가 시 측정 대상이 어디까지인지

#### 5. [범위] 선택 구현 범위 축소

**판단 근거**
실제 개발 기간이 4주(09/30~10/27)이고 필수 기능 3개(OCR / LLM 가이드 생성 / 챗봇)만으로도 빠듯하다고 판단했습니다. 선택 구현은 "시각/음성 콘텐츠 변환(TTS)" 1개만 진행하고, 나머지는 확장 계획으로 문서화하려 합니다. 타겟 사용자를 고령층 + 보호자로 잡았기 때문에 음성 안내가 기획상 자연스럽게 연결됩니다.

**확인하고 싶은 점**
무리한 축소는 아닌지, 평가상 선택 구현 개수가 중요한지
