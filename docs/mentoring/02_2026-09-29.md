### 프로토타입에서 실제로 돌아가는 것

- 약 이름 검색: 심평원 약제급여목록 (먹는 약 17,450개)
- 안전성 점검: 심평원 DUR (병용금기, 동일성분, 효능군 중복, 노인주의, 연령금기, 다제약물)
- 생활습관 안내: 직접 만든 팩트 테이블 v0.2 (10개 질환)
- OCR, 챗봇 답변, 안내문, 로그인, 포인트는 아직 가짜 데이터

### 작업 방식

- 순서는 Figma 화면 먼저, 그 화면 기준으로 요구사항과 API, ERD를 맞추고, 리뷰한 뒤 프로토타입으로 확인
- 문서 초안, Figma 정리, 문서끼리 맞는지 검토, 프로토타입 제작은 AI 도구(Claude)로 하고 PM이 검수. 피처 설계는 각 담당자가 정함
- 모든 문서와 Figma 페이지에 변경 이력. 바꿀 때마다 이전 값과 바뀐 값을 같이 남김
- 팀원이 수정안을 올리면 PM이 리뷰해서 답장하고, 정할 건 미팅 안건으로 모아서 한 번에 정함
- 데이터는 공식 출처에서 각자 받고 git에는 출처와 경로만 둠
- 병용금기 같은 안전성 판정은 DB 조회로 하고, LLM은 안내문 문장 만드는 데만 씀

## 3. 현재 막힌 문제 / 검증이 필요한 사항

1. **[진행 방식]** 프로토타입 중심으로 진행하는 방식
   - 판단 근거: 텍스트 기획문서만 보고 회의하니 서로 이해하는 정도가 달라서 진행이 잘 안 됐습니다. 프로토타입을 띄워놓고 화면을 보면서 고치니 빠진 화면이나 문서끼리 안 맞는 부분이 바로 보였습니다. 앞으로는 프로토타입을 만들면서 수정하고, 바뀐 내용을 Figma와 문서에 다시 반영하는 식으로 진행하려고 합니다.
   - 확인하고 싶은 점:
     - 기준을 Figma로 둘지, 프로토타입으로 둘지
     - 평가 제출용 산출물(요구사항, API, ERD, 와이어프레임)은 어떻게 같이 관리하면 좋을지
