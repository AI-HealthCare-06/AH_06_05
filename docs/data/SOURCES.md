## 0. 원칙

- **원본 데이터는 git에 올리지 않습니다.** 파일이 크고(병용금기 CSV 254MB), 기관 배포 조건이 제각각이라 Public 저장소에 두지 않습니다.
- 각자 **아래 공식 출처에서 직접 받아** `data/raw/` 아래 지정 경로에 둡니다. `data/raw/`는 `.gitignore`로 제외되어 있습니다.
- 파일 이름은 **받은 원본 이름 그대로** 둡니다. 적재 스크립트는 이 문서의 경로를 기준으로 읽습니다.
- 기준일이 바뀐 새 파일을 쓰기 시작하면 이 문서의 기준일 · 건수와 변경 이력을 같이 고칩니다.
- API 키는 `.env`에만 넣고, `.env.example`에는 키 이름만 적습니다.

```
data/raw/
├─ dur/     심평원 DUR 품목리스트 (공공데이터포털 CSV · 심평원 게시 xlsx) · m.db
├─ hira/    심평원 상병마스터 · 약제급여목록
└─ nhis/    국민건강보험공단 건강검진검사항목코드
```

## 2. 파일별 메모

### 1. DUR 의약품 목록 (공공데이터포털 CSV)
- 인코딩 **cp949** — `pd.read_csv(path, encoding="cp949")`
- 병용금기는 **제품 쌍 단위 873,147행** → 성분 쌍으로 정규화하면 약 9.7만 쌍 (A<B로 정렬해 중복 제거)
- 병용금기 컬럼: `성분명A · 성분코드A · 제품코드A · 제품명A · 업체명A …` / `…B` / 금기 사유 · 공고일
- 복합제는 대표 성분명만 표시될 수 있음 (제공 기관 안내)

### 2~6. 심평원 게시 품목리스트 (xlsx)
- 파일마다 **급여 · 비급여 시트가 따로** 있음 → 둘 다 적재
- 병용금기 파일에는 **`MTX(15mg 미만)` 시트**가 별도로 있음 (메토트렉세이트 저용량 예외)
- 공공데이터포털 CSV(6월 기준)보다 **최신(9월)** 이라, 두 출처가 겹치는 항목은 게시 xlsx를 우선할지 적재 전에 정함

### 7. `m.db`
- 요양기관용 DUR 점검 프로그램이 쓰는 로컬 DB. 공개 CSV에 없는 **병용금기 예외(TBJBD46)** · **용량주의(TBDUC200/202)** 가 들어 있음
- 공개 파일이라 파생 데이터(예: 프로토타입 `dur.json`) 사용 · 공유 가능. 원본은 용량 때문에 git에 올리지 않고 각자 받음
- 주요 테이블 (행 수)

| 테이블 | 행 수 | 쓰는 곳 |
|---|---|---|
| TBJBD43 | 194,607 | 병용금기 성분 쌍 → `dur_interaction` |
| TBJBD46 | 2,193 | 병용금기 예외 제품 → `dur_interaction_exception` |
| TBDUC230 | 531 | 노인주의 → `dur_elderly` |
| TBDUC200 · TBDUC202 | 746 · 305 | 용량주의 → `dur_dose_limit` |
| 그 외 17개 (TBDUC201 · 203 · 220 · 221 · 260 · 270 · TBDUD201 · 230 · 231 · TBJBD44 · 47 · 48 · 52 · 55 · 56 · 63 · MVERSION) | — | 용도 확인 필요 |

### 8. 상병마스터
- KCD 기반. 컬럼: `상병기호 · 한글명 · 영문명 · 완전코드구분 · 주상병사용구분 · 법정감염병구분 · 성별구분 · 상한연령 …`
- 심평원 홈페이지에서도 검색 가능 (제도·정책 > 보험기준 > 자료실 > 상병마스터)

### 9. 약제급여목록
- 조인 키: **제품코드(EDI 9자리) = 식약처 EDI_CODE** (ERD 설계 원칙 4)
- `주성분코드_동일제형` 칸이 제형 무관 동일성분 그룹 → `drug_products.ingr_group`
- 헤더에 줄바꿈이 들어간 칸이 있음 (`주성분코드\n_동일제형`) — 적재 시 컬럼명 정리

### 10. 건강검진검사항목코드
- 건강검진 결과 입력은 보류 (REQ-015). 확정되면 적재
