# 복약 안내문 사전 저장 (drug_guides)

멘토링 4회차(2026-10-13): 안내문은 실시간이 아니라 **배치로 미리 DB에 저장**하고, **사람이 확인**한다(현업에서도 필수).

## 흐름

```
[배치] 급여목록 22,045품목
   └─ 약효분류 표(medication.CLASS_NAME · CLASS_PURPOSE)로 종류 · 쓰임 만들기      ← AI 없음
        └─ drug_guides에 draft로 저장 (약 1개 = 1행)
[사람 확인] review_drug_guides.py list → 같은 내용 묶음(약 20묶음)을 읽고 approve / reject
        └─ 확인한 사람 · 시각 기록
[분석] guide_generation 단계
   └─ drug_guides에서 approved만 조회 → 먹는 법(하루 몇 번 · 며칠)은 처방 숫자로 붙임
        └─ approved가 아닌 약(draft · rejected · 저장 없음) → "처방받은 목적을 약사에게 확인해 주세요", 종류 · 출처 없음
```

- 먹는 법은 처방마다 달라서 저장하지 않고 분석 때 만든다.
- 규칙 표(`app/services/guide/medication.py`)를 고친 뒤 `generate_drug_guides.py --all`을 돌리면, **내용이 바뀐 약은 확인이 풀려서 draft로 돌아간다**(옛 내용이 승인된 채 남지 않게). 내용이 같으면 승인 상태가 유지된다.

## 허가정보 문장 (데모 약 17개)

규칙 표는 쓰임만 만들고 주의할 점이 비어 있어서, 데모 약은 **식약처 허가정보 문장**을 따로 넣는다. 파일: `app/services/guide/data/demo_guides.json`.

- 만든 방법: 샌드박스(`rag_sandbox/guide`)에서 gpt-4o-mini가 허가정보 원문 문장을 근거로 약마다 한 번에 쓰고(`prompt_ver` med-v8), 검증 규칙으로 걸러 냈다. 걸러지지 않은 문장만 남고, 부족한 약은 문장이 1~2개거나 쓰임이 비어(→ 화면은 "허가정보 원문 보기" 쪽) 있다.
- 검증 규칙의 핵심: 문장이 **인용한 원문 문장 안에 있는 내용**이어야 한다. 원문에 없는 증상 · 행동, 원문보다 센 금지("드시지 마세요")·긴급 표현("바로 병원")은 빼거나 낮춘다. 원문이 "중지한다"고만 한 것은 긴급이 아니다.
- 2026-10-16 문장 30개를 원문과 대조해 7곳을 고치고 규칙을 보강했다(시클펜 · 아이스타 · 아스피린 · 아토르스타/리피토 · 루나팜 · 아세트아미노펜 2종 · 다이아벡스/다이아폴민). **약사 · 의료진 검수는 아니다.** 사람 확인은 "문장이 근거 원문과 어긋나지 않는가"까지다.
- 넣기: `python scripts/generate_drug_guides.py --seed` → 새 약은 **draft**. 급여목록에 없는 약은 건너뛴다(missing). 같은 내용이면 확인 상태를 유지하고, 바뀌면 draft로 돌아간다. 규칙 표 재생성(`--all`)과 묶음 확인(`approve KEY`)은 이 약들을 건드리지 않는다(`model_name`이 있는 행).
- 확인: `python scripts/review_drug_guides.py drugs`가 약마다 문장과 근거 원문을 나란히 보여 준다 → `approve-drug 코드... --by 이름`. approved가 되기 전에는 화면에 나가지 않는다.
- 응답: `caution`(문자열)은 문장을 줄바꿈으로 이어 붙인 것이고, 문장별 목록은 `cautions`(배열, 명세서에 없는 추가 필드)다. `category`는 약효분류 표에서 가져온다(표에 없는 분류는 null).
- 근거: `evidence_ids`에 `{kind: "drug_details", key: 품목기준코드, field: 문장 번호(E/S), use: purpose | caution1~3, text: 원문 문장}`을 문장마다 저장한다.
- 쓰임은 샌드박스 문구("~에 쓰는 약이에요")를 그대로 쓴다. 규칙 표의 "혈압을 낮춰요" 류와는 문구가 다르다(어느 쪽으로 통일할지는 팀 결정).

## 근거 목록 (챗봇 출처)

`drug_guides.evidence_ids`에 `[{kind, key, label}]`로 근거를 저장한다. 챗봇은 답에 출처를 붙일 때 이 값을 그대로 쓴다.
- `hira_class`: 심평원 약효분류 표 (key=분류 3자리). 표에 없는 분류의 약은 빈 목록(→ 출처 없음)
- `drug_details`: 허가정보 항목 (key=품목기준코드, field=효능효과·용법용량·사용상의주의사항). 허가정보를 적재하면 추가
- 표를 고쳐 근거만 바뀐 약은 확인 상태를 유지한 채 근거만 갱신한다. 보이는 내용이 바뀐 약은 draft로 돌아간다.

## 처음 쓰는 순서

1. `aerich upgrade` (drug_guides 표 만들기)
2. 급여목록(drug_products) 적재 후 `python scripts/generate_drug_guides.py`
3. `python scripts/review_drug_guides.py list`로 묶음 확인 → `approve KEY --by 이름`
   (확인 전에는 모든 약에 "약사에게 확인" 문구만 나간다)

## 왜 HTTP 관리자 화면이 없나

서버에 관리자 권한 구분이 없어서, API로 열면 누구나 안내문을 승인할 수 있다. 서버 안에서 팀원이 직접 실행하는 스크립트로 둔다.
관리자 권한(로그인 · 회원 영역)을 정한 뒤 화면을 만든다. → ERD v1.5 안건

## 한계 (발표 · 보고서에 그대로 적을 것)

- 쓰임 문구는 **일반적인 약효분류 설명**이다. 개인 처방의 목적을 확정하지 않으며, 약사 · 의료진의 전문 검토를 거치지 않았다. 팀원이 확인한 것은 "약효분류와 예시 약이 맞는지"까지다.
- 묶음은 심평원 약효분류 3자리 기준이라, 한 분류 안에 성격이 다른 약이 섞일 수 있다. 확인 때 묶음 전체에서 고르게 뽑은 예시 5개를 보지만 전수 확인은 아니다.
- 같은 분류에 쓰임이 다른 약이 섞인 분류(219 기타 순환계, 339 기타 혈액, 117 정신신경용제, 243 갑상선, 245 부신 호르몬)는 표에서 뺐다. 처음 표에 넣었다가 묶음 확인 때 예시 약이 안 맞아서 뺐다 (예: 갑상선 호르몬을 줄이는 약에 "보충"이라고 나옴).
- 표에 없는 분류(약 8천여 개, 주사 · 외용 포함)는 "약사에게 확인" 문구만 나간다.
- 주의할 점(caution)은 허가정보 문장을 넣은 데모 약 17개만 채워져 있고, 나머지 약은 비어 있다(허가정보 42,707건 전체를 AI로 돌리지 않음).
- 데모 약 17개의 문장은 AI가 쓰고 규칙으로 걸러 낸 것이다(prompt_ver · model_name에 남음). 나머지 약은 규칙 표로 만든 것이다. 두 가지 모두 같은 확인 절차(approved만 노출)를 쓴다.
- 허가정보 문장은 약사 · 의료진 검수를 거치지 않았다. 사람이 확인하는 것은 "문장이 근거 원문과 어긋나지 않는가"까지다.
