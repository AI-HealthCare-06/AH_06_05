# 약봉투 읽기 (10/15)

앱은 "처방전과 약봉투를 찍어 주세요"라고 안내하지만, 표 읽기는 처방전의 "투약일수" 머리글만 알았다. 약봉투 샘플 p1 · r2는 머리글이 "투약량 · 횟수 · 일수"라 읽지 못하고 "다시 찍어 주세요"로 끝났다. 그래서 약봉투 표를 따로 읽는다 (`app/services/ocr/pouch.py`).

## 어떻게 읽나

- 처방전 표를 못 읽었을 때(`parse_table`이 None)만 약봉투로 다시 본다 (`pipeline.read`). 처방전 읽기 결과는 바뀌지 않는다 (샘플 15장 중 p1 · r2만 달라짐).
- **글자 순서가 아니라 위치로 읽는다.** CLOVA 글자 목록 순서는 보장되지 않는다.
  1. 같은 줄에 왼쪽부터 "투약량 · 횟수 · 일수"가 있는 곳이 머리글이다. 한 줄에 모여 있지 않으면 머리글이 아니다 (영수증 띠의 "투약일수" 하나는 머리글이 아님, 0031과 같은 이유).
  2. 숫자는 세 낱말 아래 칸 위치로 1회량 · 하루 횟수 · 총 일수에 나눈다. 칸 밖의 숫자(영수증 띠의 전화번호 · 승인번호)는 읽지 않는다.
  3. 약 이름은 투약량 칸 왼쪽의 **큰 글자 줄**이다. 카드형(p1)은 이름 아래의 "[분류]" · 성분 · 복약 안내 문장이 이름보다 작아서 글자 높이를 두 무리로 나눠 큰 쪽을 이름으로 본다 (p1 실측: 이름 23~29, 나머지 15~21). 한 줄형(r2)은 높이가 거의 같아 모든 줄이 이름이다. 이름은 왼쪽 끝에서 시작하고 "["로 시작하지 않는다.
  4. 카드형은 숫자가 카드 가운데에 있어서 이름 줄 사이의 가운데선으로 칸을 나눠 숫자를 이름에 붙인다.
  5. 숫자가 하나도 없는 줄이 표의 처음이나 끝에 있으면 버리고, 가운데면 남겨서 "못 읽음"으로 사용자가 채우게 한다.
- 저장은 `doc_type = pill_bag`. 약봉투에는 교부일 · 병원 · 출생연도가 없어서 **조제일만** 읽어 `issued_date`에 넣고(API 명세서 O-2: 약봉투는 조제일), 병원 · 용법 · 출생연도는 비운다. 조제일은 "조제일" · "조제일자" 라벨 바로 뒤의 날짜만 쓰고, 날짜가 둘 이상 다르면 비워서 확인하게 한다. 질병분류기호도 읽지 않아 `diseaseCodes`는 빈 배열이다 (RG-05-E1).
- 영수증 띠(환자 · 약사 이름, 주소, 전화, 승인번호)는 이름 영역도 숫자 칸도 아니라서 읽지 않는다. 마스킹 규칙은 승인번호 · 사업자번호 · 주소를 가리지 않으므로 **이 띠를 저장 범위에 넣지 않는 것이 전제**다 (`ocr_mask.md`).
- 이름 끝이 "···"로 잘린 약(p1의 `슈가메트서방정5/100···`)은 약 마스터에서 한 약과만 글자가 맞아도 **자동 확정하지 않고** 후보로 올려 사용자가 고른다 (`CUT_FLAG`). 함량이 잘렸을 수 있어서다. 후보에는 다른 함량도 같이 올라온다 (p1에서 확인).

## 확인한 것 (실제 CLOVA 결과 저장본 기준)

| 샘플 | 결과 |
|---|---|
| p1 (카드형, 8약) | 8줄 · 이름 8개 · 숫자 칸 일치 (샘플이 전부 1/6/3). 조제일 2020-02-07. 약 마스터 대조: 6줄 확정, 잘린 이름 2줄은 확인 필요 |
| r2 (한 줄형, 3약) | 3줄 · 이름 3개 · 1/3/3. 조제일은 못 읽음(날짜가 "조제일자: 복용완료일 …" 모양) → 확인 항목. 약 마스터 대조: 2줄 확정, 1줄(세토펜8시간이알서방정)은 비슷한 약이 있어 확인 필요 |
| p2 (500px) | 머리글 "일수"가 "밀수"로 잘못 읽혀 지원 안 함. 촬영 크기 검사(짧은 쪽 400px)에서 먼저 걸러진다 |
| 그 밖의 12장(처방전 · 다른 사진) | 읽기 결과가 수정 전과 같다 |

테스트는 실제 사진 데이터를 저장소에 넣지 않고, 위 사진에서 잰 모양(글자 높이 · 칸 간격 · 영수증 띠)을 본뜬 합성 데이터로 한다 (`app/tests/ocr_pipeline/test_pouch.py`, `app/tests/ocr_apis/test_ocr_apis.py`). 저장해 둔 결과를 지금 코드로 읽어 보려면 `python scripts/read_saved_ocr.py <결과.json>` (CLOVA 호출 없음, DB 저장 없음).

## 한계 (샘플 3종 중 2종으로 만든 규칙)

- 샘플 p1 · r2 두 종류만 확인했다. 다른 약국의 양식은 머리글 낱말이나 배치가 다를 수 있어 읽지 못하고 "다시 찍어 주세요"가 된다 (잘못 읽기보다 못 읽는 쪽으로 기운다).
- 이름이 두 줄로 꺾이면 줄마다 약 하나로 읽힐 수 있다. 이때 숫자 칸 수와 약 줄 수가 달라 `row_count_mismatch`가 켜진다.
- 해상도가 낮거나 글자가 깨진 약봉투(p2)는 읽지 못한다.
- 높이 기준(카드형 이름 판별)은 p1 한 장의 실측이다. 이름과 안내 문장의 글자 크기 차이가 작은 양식이면 안내 문장이 약 줄로 섞일 수 있다 → 줄 수 불일치 표시와 사용자 확인이 마지막 방어선이다.
- 같은 약을 처방전과 약봉투로 두 번 올리면 약봉투는 병원 이름이 없어 중복 합치기(`content_key`)가 되지 않는다.
- 약 줄의 복약 안내 문장(쪼개지 마세요 등)은 읽지 않는다.
