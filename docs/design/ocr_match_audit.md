# 약 이름 맞추기 · 마스킹 다시 점검 (10/15)

실제 급여목록(약 22,045개)으로 `NameMatcher`를 다시 쟀다. 측정 스크립트는 저장소에 넣지 않았다 (약 이름 맞추기 한 번에 22,000개를 훑어 느리다. 표본 1,500~2,000개, 난수 씨앗 고정).

## 찾은 문제 · 고친 것

| 문제 | 원인 | 고침 |
|---|---|---|
| "데파코트서방정500mg"로 읽었는데 250mg로 확정 | 급여목록 이름 234개(1%)가 `㎎` `㎍` `㎖` 같은 호환 문자를 쓴다. 질문 쪽만 `mg`로 풀고 목록 쪽은 풀지 않아, 500㎎ 이름이 글자가 달라 보였다 | `unify()`가 NFKC로 양쪽을 같이 푼다 |
| 목록에 있는 이름을 그대로 넣었는데 못 찾음/다른 약 (`브록솔정(암브록솔염산염)`) | "브록솔정"과 "록솔정"은 2글자 조각 집합이 같아 점수가 같다. 동점이면 제품 번호로 정해졌다 | 이름이 글자 그대로 같은 제품이 동점에서 먼저 |
| 함량 숫자를 한 자리 잘못 읽으면 다른 함량으로 확정 (피엠에스로수바스타틴정 5 → 20) | 글자가 거의 같아 점수가 높다 | 읽은 이름의 숫자가 맞는 약의 숫자와 다르면 확정하지 않고 사용자가 고른다 (`Decision.strength`) |
| 3글자 이름(세롤주 · 썸디정 · 아트정 · 올펜정 · 울셋정 · 캄랍주 · 코푸정 · 타코실 8개)은 항상 "못 찾음" | 4글자 미만은 찾지 않는 규칙 | 급여목록 이름과 글자 그대로 같을 때만 찾는다 (2글자 이름 "산소" · "티씰"은 여전히 안 찾는다 — 최종 코드로 10개 모두 확인) |

| 시험 | 전 | 후 |
|---|---|---|
| 목록 이름 그대로 1,500개: 다른 약으로 확정 | 2 | 0 |
| 목록 이름 그대로 1,500개: 못 찾음 | 3 | 0 (표본의 세 개 — 브록솔정 · 캄랍주 · 나이시드캡슐150㎎ — 를 최종 코드로 다시 확인) |
| 글자 하나 바꾸기 2,000개: 조용히 틀림 (확정인데 다른 약) | 0 | 0 |
| 함량 숫자 한 자리 바꾸기 1,500개: 다른 함량으로 확정 | 49 | 21 |
| 〃 사용자가 고르게 넘어간 것 | 484 | 1,384 |

남은 21개는 잘못 읽은 숫자가 **우연히 다른 실제 함량**이 된 경우(60 → 30 · 100 → 200 등)라 이름만으로는 구분할 수 없다. 잘못 읽은 숫자가 목록에 없는 함량이면 이제 사용자가 고른다. 대가는 사용자가 고르는 줄이 늘어나는 것이다 (숫자를 잘못 읽었을 때만. 실제 사진 17장의 결과는 하나도 바뀌지 않았다).

## 마스킹에서 놓치던 모양 (고침)

공백으로만 나뉜 주민번호(`900101 1234567`) · 점으로 나뉜 전화번호(`010.1234.5678`) · 국제번호(`+82 10-1234-5678`) · 앞 세 자리 뒤에 공백이 낀 번호 · 끝자리가 하나 덜 읽힌 번호 · 글자 사이에 공백이 낀 `홍 길 동 님` · 연월일이 다 있는 `1990년 1월 1일생`. 약 이름 22,045개에 적용해도 바뀌는 것은 0개다.

못 가리는 것으로 남는 것: 환자 주소(양식에 없고 저장하는 칸에도 읽어 들이지 않는다), 라벨도 신호 낱말도 없는 이름, 6자리 숫자만 있는 생년월일(`990101`).
