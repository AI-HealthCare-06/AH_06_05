## 1. 한 줄 요약

AI에게는 답에 필요한 것만 보낸다. 질문, 진단받은 질환, 먹는 약(이름, 성분, 쓰임, 먹는 법), 나이, 최근 4번 대화가 전부다. 이름, 이메일, 그 밖의 건강 정보는 보내지 않는다. 동의가 없으면 질문과 대화만 보낸다.

## 2. 질문이 들어오는 순서

| 순서 | 하는 일 | 원문을 보나 | 근거 |
|---|---|---|---|
| 1 | 앞뒤 공백을 지우고 1~500자가 아니면 거절 (400) | 예 | 명세서 H-3 |
| 2 | 1층 규칙과 문맥 파악 (AI 없음). 걸리면 원문을 저장하지 않고 긴급 카드 | 예 | 설계 메모 4-6 |
| 3 | 안전 모드인 대화에서 약의 양을 물으면 원문 없이 위기 카드 | 예 | #116, v0.37 |
| 4 | 주민번호, 전화번호, 이메일, 생년월일 같은 번호를 가린 뒤 저장 | 가린 글 | #168 (병합 전) |
| 5 | 저장된 글로 2층, 분류, 근거 검색, 답 만들기 | 가린 글 | |

번호를 가리기 전에 1층이 원문을 보는 것은 일부러 정한 순서다. 번호를 가려도 위험 판단은 달라지지 않는다.

## 3. AI 호출마다 들어가는 것

| AI 호출 | 질문 | 고정 정보 | 최근 대화 | 그 밖 |
|---|---|---|---|---|
| 2층 위험 판단 (guard) | 예 | 아니오 | 아니오 | 없음 |
| 분류 (classify) | 예 | 예 | 최근 4번 | 지시어 풀이 결과(약 이름) |
| 근거 검색: 질문 고쳐 쓰기, 고르기, 판정 (RAG) | 예 | 약 이름과 질환만 | 아니오 | 후보 근거 문장 |
| 답 만들기 (answer) | 예 | 예 | 최근 4번 | 분류 결과, 고른 근거 |

고정 정보 = 나이, 진단받은 질환(팩트표에 있는 것만, 처방전과 내 정보를 합침), 먹는 약(이름, 성분, 쓰임, 처방대로 먹는 법). `fixed_info_text`(app/services/chatbot/context.py) 한 곳에서 만든다.

## 4. 보내지 않는 것

| 무엇 | 이유 |
|---|---|
| 이름, 이메일, 성별, 출생연도 원값 | 답에 필요 없음. 나이만 계산해서 보냄 |
| 분석의 약끼리 경고 문장 | AI가 다시 판단하지 않게 템플릿으로만 보여 줌 (NFR-032, ⑤) |
| 임신, 투석, 흡연, 음주, 키와 몸무게, 예정 검사 | 지금 답 만들기에 쓰는 규칙이 없음. 넣으면 AI가 근거 없이 쓸 수 있음 |
| 처방전 원문, 병원 이름, 교부일 | 답에 필요 없음 (원문은 저장도 하지 않음, 10/15) |
| 1층에 걸린 질문과 그 답 | 원문이 없음. 대화 기억에서도 뺌 |
| 범위 밖 질문과 그 답 | 다음 답의 노이즈가 됨 (#140) |

서버 로그도 같은 기준이다. 근거 없음 로그에는 질문 글과 약 이름 없이 약과 질환의 개수만 남긴다 (#124).

## 5. 동의와 모드

| 상태 | 고정 정보 | 비고 |
|---|---|---|
| 민감정보 동의 없음 | 넣지 않음 (나이도 없음) | 일반 정보만 (10/6 결정, 명세서 H-1) |
| 동의 있음, 붙은 분석 없음 | 가장 최근 완료 분석에서 | #162 (병합 전). 지금 main은 일반 모드 |
| 동의 있음, 분석 있음 | 가장 최근 맥락 카드의 분석, 없으면 대화를 시작한 분석 | |

## 6. 가드레일 범위

| 층 | 지금 범위 | 정할 것 |
|---|---|---|
| 입력 1층 (규칙) | 분명한 응급과 자해. 애매한 말은 2층으로 | 유지 |
| 입력 2층 (AI) | 질문 하나만 보고 none, emergency, crisis | 앞 대화와 가벼운 괴로움은 시연 뒤 (#143) |
| 고정 문구 | 범위 밖, 괴로움, 인사, 말 이상 | 유지 |
| 출력 (규칙) | 근거에 없는 숫자, 허가정보에 없는 빠뜨린 약 안내, 양이나 복용을 바꾸라는 말, 먹는 때 | 아래 |

출력 가드레일 측정(#129 채연 리뷰): 위험한 글을 통과시킨 것 0건, 안전한 상담 안내를 잘못 막은 것 4건, 일부러 쓴 잘못된 문장 77개 중 29개를 못 거름.

(제안) 시연 전에는 출력 가드레일 범위를 늘리지도 줄이지도 않는다. 멘토님 말씀처럼 계속 발목을 잡는 곳은 "잘못 막은 것 4건"인데, 고치려면 실제 호출로 다시 재야 하고 지금은 캠프 OpenAI 키가 401로 막혀 있다.

## 7. QA를 LLM으로 돌리는 범위

(제안) 골든셋 문항(`scripts/chatbot/run_golden.py`)의 답을 LLM 채점기로 "꼭 들어갈 것, 들어가면 안 될 것"에 맞춰 1차 채점하고, 사람이 어긋난 것만 본다. 갈래 일치는 지금처럼 코드로 비교한다. 키가 살아나야 시작할 수 있다.
