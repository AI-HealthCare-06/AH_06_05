# OCR 호출 전 검사 (멘토링 4회차 — 처방전이 아닌 사진 · 중복 사진을 OCR 전에 거르기)

`app/services/ocr/precheck.py` · 연결은 `prescriptions.run_job`.

## 흐름

```
업로드(O-1) → 형식 · 크기 검사(400) ─┐
                                      ↓
                [OCR 호출 전]  ① 바이트가 같은 사진은 두 번째부터 건너뜀        (호출 안 함)
                               ② 짧은 쪽이 400px 미만이면 "다시 찍기"(Q)       (호출 안 함)
                               ②' 너무 흐리면 "다시 찍기"(Q)                  (호출 안 함)
                                      ↓
                              CLOVA → 읽기 → 표 → 약 이름 맞추기
                                      ↓
                [OCR 후]       ③ 병원 · 교부일 · 약 목록이 모두 같은 처방전이 이미 있으면 새로 저장 안 함
                               ④ 읽을 수 없으면 Q(흐림) · 문서 아님이면 D
```

## 기준과 근거

| 검사 | 기준 | 근거 |
|---|---|---|
| 작은 사진 | 짧은 쪽 < 400px | 실제 CLOVA 시험 9장 중 못 읽힌 두 장이 291px · 235px, 나머지는 440px 이상. 휴대폰 사진은 보통 1000px 이상이라 정상 촬영은 걸리지 않음 |
| 흐린 사진 | 글자가 가장 많은 칸 3개의 선명도 < 100 (`OCR_MIN_SHARPNESS`, 0이면 끔) | 10/13 시험 사진: 못 읽힌 흐린 사진 11, 흐려도 읽힌 사진 232, 글자가 적은 사진 404~1718, 정상 사진 940 이상. 100은 못 읽힌 쪽(11)과 읽힌 쪽(232) 사이 |
| 같은 파일 | SHA-256 동일 | 바이트가 같으면 오탐이 없음 |
| 같은 처방전 | (병원, 교부일, 약 목록 + 복용 숫자) 동일 | 읽은 내용이 같을 때만 합침. 하나라도 비면 합치지 않음 |

선명도는 흑백 축소본(긴 쪽 1000px)에 라플라시안 필터를 걸어 가로 4 × 세로 6칸으로 나눈 뒤, 분산이 큰 3칸의 평균으로 잰다. 전체 평균은 글자가 적은 처방전(흰 종이가 대부분)을 흐리다고 잘못 판정하므로 쓰지 않는다. 필터가 처리하지 않는 가장자리 1픽셀은 가짜 신호(흰 종이도 186)라 뺀다. 4천만 픽셀이 넘거나 열 수 없는 파일은 재지 않고 OCR로 보낸다. 이미지를 여는 계산이라 `run_job`에서 별도 스레드로 돌린다.
**한계**: 기준은 시험 사진 몇 장에서 정했다. 실제 휴대폰 사진이 모이면 다시 확인한다 (너무 엄격하면 정상 사진을 막고, 느슨하면 OCR 호출이 낭비된다 — 값을 환경변수로 조절).
**새 의존성**: Pillow (`pyproject.toml` app 그룹, `uv.lock`). PR 설명에 적을 것.

크기는 이미지를 열지 않고 파일 머리말만 읽는다 (JPEG · PNG). Pillow와 대조해 실제 샘플 9장 · 시스템 이미지 · 진행형 · 흑백 · CMYK · EXIF · PNG 변형 423장이 모두 일치했다.
머리말을 읽을 수 없는 파일은 **거르지 않고 OCR로 보낸다** (정상 사진을 잘못 막는 쪽이 더 나쁘다).

## 일부러 하지 않은 것 (이유)

- **비슷한 사진 찾기(이미지 비교)**: 같은 사진을 재압축 · 축소한 것과 숫자 한 글자만 다른 처방전이 구분되지 않았다 (글자 한 개 차이의 칸별 차이 0.012~0.024, 같은 사진 변형 0.006~0.054). 오탐하면 처방전이 사라지므로 하지 않는다.
- **밝기 검사**: 어둡게 만든 시험 사진(평균 밝기 136)도 정상으로 읽혀서 거를 근거가 없다.
- **처방전이 아닌 사진을 OCR 전에 찾기**: 손글씨 처방전은 배경이 하얗지 않아서(샘플 r1) 밝기로 가르면 정상 사진을 막는다. 현재는 OCR 결과(`NOT_A_DOCUMENT`)로 판단하며, 이 경우 OCR 호출 1회는 쓴다.

## 화면 · API에 미치는 영향

- 작은 사진 · 흐린 사진은 기존 `IMAGE_QUALITY_LOW`로 돌아간다 (새 코드 없음).
- 똑같은 사진 · 같은 처방전은 오류 없이 처리되고, 응답의 `duplicatedFiles`로 어느 사진이 어느 기존 기록과 같은지 알려 준다. 같은 기록은 `prescriptionIds`에 한 번만 나온다.
- 다른 날 같은 처방전을 다시 올리면 새로 저장하지 않고 기존 기록을 쓰게 안내한다 (`duplicatedFiles`, 수인님 결정 10/14 — `ocr_mask.md` 2장).
