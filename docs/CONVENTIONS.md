# 협업 규칙

> **상태: 초안** — 팀 협의 후 확정

---

## 브랜치 전략

```
main        배포 가능한 안정 버전 (직접 push 금지)
 └ develop  개발 통합 브랜치
    └ feature/*   기능 개발
    └ fix/*       버그 수정
```

### 규칙

- **`main` 직접 push 금지** — 반드시 PR로 병합
- 모든 작업은 `feature/*` 브랜치에서 진행
- `feature` → `develop` → `main` 순서로 병합

### 브랜치 이름

```
feature/ocr-upload
feature/chatbot-api
fix/login-error
docs/requirements
```

---

## 커밋 메시지

```
<type>: <내용>
```

| type | 용도 |
|---|---|
| `feat` | 새 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 작업 |
| `style` | 코드 포맷팅 (동작 변경 없음) |
| `refactor` | 리팩터링 |
| `test` | 테스트 코드 |
| `chore` | 빌드·설정·패키지 등 |

예시
```
feat: 처방전 이미지 업로드 API 구현
fix: OCR 결과 한글 깨짐 수정
docs: 요구사항 정의서 초안 작성
```

- 한글로 작성
- 제목은 50자 이내, 마침표 없이

---

## Pull Request

### 규칙

- **리뷰어 1명 이상 승인 후 병합**
- 작은 단위로 자주 올리기 (리뷰 부담 감소)
- 리뷰는 **결과물 중심**으로, 쿠션어 사용

### PR 템플릿

```markdown
## 작업 내용
-

## 변경 사항
-

## 테스트 여부
- [ ] 로컬 동작 확인
- [ ] 기존 기능 영향 없음 확인

## 리뷰 요청 사항
-
```

---

## 이슈 관리

- 작업 단위로 이슈 생성 후 브랜치 작업
- PR 본문에 `Closes #이슈번호` 표기
- 라벨 예시: `feature` `bug` `docs` `AI` `frontend` `backend` `infra`

## 보안 (중요)

> **이 저장소는 Public입니다.**

절대 커밋 금지
- `.env` 및 모든 환경변수 파일
- OpenAI / CLOVA / AWS 등 **API 키 · 토큰 · 시크릿**
- 실제 진료기록 · 처방전 등 **개인정보 포함 파일**
- DB 접속 정보

지켜야 할 것
- 환경변수는 `.env.example`에 **키 이름만** 기재
- 테스트 샘플은 비식별 처리 후 사용
- 키가 실수로 커밋되면 **즉시 해당 키를 폐기하고 재발급** (커밋 삭제만으로는 유출이 회수되지 않음)
