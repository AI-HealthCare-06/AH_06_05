# frontend/AGENTS.md

> AI 코딩 도구가 `frontend/`(Expo 앱)에서 작업할 때 읽는 파일. 루트 `AGENTS.md`는 그대로 따르고, 여기에는 앱 작업에만 해당하는 것만 둠. 바꿀 때는 PR로 고치고 맨 아래 변경 이력을 남김
> 원칙: 루트와 같음. 한 줄마다 "이 줄을 지우면 AI가 실수할까?"를 묻고 아니면 지움. 구조와 화면 규칙은 여기에 쓰지 않고 아래 문서를 봄

## 먼저 읽을 것

- 구조, 폴더, 타입, 보안: [SYSTEM_DESIGN.md](../SYSTEM_DESIGN.md) 8장 (앱)
- 화면 규칙, 색과 글자 값, 부품: [DESIGN.md](../DESIGN.md)
- 화면 번호와 화면별 API: `docs/planning/screen_id_table.md`, `docs/planning/` API 명세서, 와이어프레임

## 화면 하나를 만드는 순서

1. 탐색: 화면 번호표, 와이어프레임, 명세서에서 그 화면의 문구, 상태(빈 화면, 오류), 부르는 API를 찾음. 바로 고치지 않음
2. 가짜 응답으로 먼저: 서버가 없어도 `EXPO_PUBLIC_USE_MOCK=true`로 화면을 끝까지 만듦. 가짜 응답은 명세서 모양 그대로
3. 확인: `npm run typecheck`를 통과시키고 Expo Go로 직접 봄. 무엇을 눌러 보고 어떤 상태까지 봤는지 적음. "될 것 같다"로 끝내지 않음
   - 자동 시험(Jest)은 아직 없음(10/14 회의에서 CI와 함께 2순위로 정함). 생기기 전까지는 위 확인으로 대신함

## 꼭 지킬 것

- API를 더하거나 바꾸면 명세서부터 고치고, 같은 PR에서 가짜 응답(`shared/api/mock.ts`)도 고침
- 피처 담당이 화면부터 서버까지 맡음(10/7). 남의 피처 폴더(`src/features/<피처>`)를 고칠 때는 담당에게 먼저 알림
- 앱 로그(`console.log` 포함)에 건강 정보, OCR 글, 처방전 사진, 대화 내용을 남기지 않음
- 린트와 포맷 도구(ESLint, Prettier)는 아직 정하지 않음. 상관없는 PR에 끼워 넣지 않음
